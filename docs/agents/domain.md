# Domain docs

## Before exploring

This repository uses a single-context layout.

- Read `GLOSSARY.md` at the repository root.
- Read decisions in `docs/adr/` relevant to the area being explored.

If these files are absent, proceed silently.
The domain-modeling skill creates them when terms or decisions
are resolved.

## Vocabulary and decisions

Use the glossary's terms in proposals, issues, tests, and code.
If a needed concept is missing, reconsider the wording or record
the gap for domain modeling.

Explicitly flag proposals that conflict with an existing ADR,
referencing the decision and explaining the proposed change.
